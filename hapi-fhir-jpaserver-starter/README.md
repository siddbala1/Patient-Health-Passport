# HAPI FHIR Server — Local Fake Hospital

A local FHIR R4 server that acts as a fake hospital database 
for development and testing. Populated with 114 synthetic 
patients generated by Synthea.

## What It Does
- Stores and serves patient records in FHIR R4 format
- Responds to the same API calls that real hospitals like 
  Epic and Cerner respond to
- Acts as Data Source 2 for the Health Information Network

## How It Relates to the Project
1. Synthea generates fake patients as JSON files
2. Those files are loaded into this HAPI FHIR server
3. This server behaves exactly like a real hospital FHIR endpoint
4. The backend queries it to retrieve patient records
5. The patient record is displayed as a JSON file at `http://localhost:3000/callback` after auth flow

## Setup Instructions

### Prerequisites
- Java JDK v21+
- Apache Maven v3.9+

### Build the Server
```bash
cd hapi-fhir-jpaserver-starter
mvn clean install -DskipTests
```

### Configure application.yaml
In `src/main/resources/application.yaml`, ensure these 
settings are uncommented and set:
```yaml
allow_external_references: true
enforce_referential_integrity_on_delete: false
enforce_referential_integrity_on_write: false
auto_create_placeholder_reference_targets: true
```

### Start the Server
Run this in a dedicated terminal — keep it running:
```bash
mvn spring-boot:run
```

### Verify It's Running
Visit: `http://localhost:8080/fhir/metadata`

### Load Synthetic Patients
Run this from the synthea folder after generating patients:
```bash
for f in output/fhir/*.json; do
  curl -X POST http://localhost:8080/fhir \
    -H "Content-Type: application/fhir+json" \
    -d @"$f"
  echo "Loaded: $f"
done
```

### Verify Patients Loaded
Visit: `http://localhost:8080/fhir/Patient?_summary=count`
Expected: `"total": 114`

## Key FHIR Endpoints
| Endpoint | What It Returns |
|----------|----------------|
| `/fhir/Patient` | All patients |
| `/fhir/Patient?name=Walton` | Search by name |
| `/fhir/Condition?patient={id}` | Patient's conditions |
| `/fhir/MedicationRequest?patient={id}` | Patient's medications |
| `/fhir/Observation?patient={id}` | Patient's lab results |

Endpoint:                        What it returns:  
/fhir/Patient                     All patients 
/fhir/Patient?name=Walton         Search by name (Ex: "Walton")
/fhir/Condition?patient={id}      Patient's conditions
/fhir/MedicationRequest?patient={id}  Patient's medications
/fhir/Observation?patient={id}    Patient's lab results

These are only 3 of at least 150 resource types defined in FHIR R4. The backend currently only pulls these 3 types for simplicity, 
but the system is designed to easily expand to more resource types in the future.


## Notes
- Server runs on port 8080
- Data is stored in an embedded H2 database
- Data is lost when server restarts (development only)
- In production this would be replaced by a persistent 
  HIPAA-compliant database
